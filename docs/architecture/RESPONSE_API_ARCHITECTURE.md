# Response API Architecture

**Status**: ✅ Supported (Primary API for new implementations)
**Compatibility**: OpenAI Responses API compatible
**Introduced**: Session 14 (Multi-stream fix)
**Last Updated**: Session 52 (2026-02-09)

---

## Overview

The **Response API** (`/v1/responses/chat/completions`) is ADEPT's primary API for chat completions, supporting streaming, tool calling, and all advanced LLM features. It provides OpenAI-compatible interfaces while leveraging ADEPT's multi-agent orchestration capabilities.

**Key Principle**: The Response API is the **required standard** for all new implementations, tests, and integrations.

---

## Architecture

### Three-Tier Request Flow

```
Client Request
    ↓
[Tier 1] Agent Gateway (agent_gateway:8081)
    ├─ JWT Authentication (Keycloak)
    ├─ CORS Handling
    └─ Transparent Proxy
        ↓
[Tier 2] Orchestration Service (orchestration_service:8084)
    ├─ ScientificWorkflowAgent
    ├─ Multi-Agent Orchestration
    ├─ Tool Management (18 built-in + external)
    ├─ PostgreSQL State (AsyncPostgresSaver)
    └─ LangGraph Checkpointing
        ↓
[Tier 3] MCP Tool Servers (Stateless Executors)
    ├─ mcp_server (Scientific tools)
    ├─ hpc_mcp_server (HPC pipelines)
    └─ sandbox_mcp_server (Code execution)
```

### Service Responsibilities

**Tier 1: Agent Gateway** (`src/agentic_framework_pkg/agent_gateway/`)
- **Authentication**: JWT validation via Keycloak
- **Routing**: Transparent proxy to Tier 2
- **CORS**: Cross-origin request handling
- **No Business Logic**: Pure authentication proxy

**Tier 2: Orchestration Service** (`src/agentic_framework_pkg/orchestration_service/`)
- **Core Logic**: ScientificWorkflowAgent implementation
- **State Management**: PostgreSQL-backed persistence
- **Tool Orchestration**: 18 built-in MCP tools + dynamic external tools
- **Multi-Agent Sessions**: Router mode and Graph mode execution

**Tier 3: MCP Servers** (Stateless)
- **Tool Execution**: CSV RAG, UniProt, PubChem, BLAST, AlphaFold, code execution
- **Session Isolation**: Session-scoped directories and resources
- **No State**: All state lives in Tier 2

## API Endpoints

### Primary Endpoint

```
POST /v1/responses/chat/completions
```

**Purpose**: Chat completion with streaming support and tool calling

**Headers**:
```http
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
X-Thread-Id: <thread_id>  (required)
X-Session-Id: <session_id>  (optional, defaults to X-Thread-Id)
```

**Request Body**:
```json
{
  "model": "agentic-framework:scientific-agent-v1",
  "messages": [
    {"role": "user", "content": "What is the capital of France?"}
  ],
  "stream": true,
  "temperature": 0.7,
  "max_tokens": 500
}
```

**Response (Streaming)**:
```
data: {"id": "chatcmpl-123", "object": "chat.completion.chunk", ...}
data: {"id": "chatcmpl-123", "object": "chat.completion.chunk", ...}
data: [DONE]
```

**Response (Non-Streaming)**:
```json
{
  "id": "chatcmpl-123",
  "object": "chat.completion",
  "created": 1234567890,
  "model": "agentic-framework:scientific-agent-v1",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "The capital of France is Paris."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 20,
    "total_tokens": 30
  }
}
```

## Session Management

### Multi-Tier Session Identifiers

The Response API uses **multi-tier session identifiers** for proper isolation:

| Session ID | Purpose | Required | Default |
|------------|---------|----------|---------|
| `X-Thread-Id` | Thread-level conversation state | ✅ Required | N/A |
| `X-Session-Id` | MCP tool execution session | Optional | Defaults to X-Thread-Id |
| `multi_agent_session_id` | Multi-agent coordination | Optional | Generated by CreateMultiAgentSession tool |
| `gateway_session_id` | A2A inter-gateway communication | Optional | Generated for A2A calls |

**Session Isolation Pattern**:
- Each MCP server creates session-scoped directories: `./data/uploaded_files/{mcp_session_id}/`
- PostgreSQL checkpoints use `thread_id` for state isolation
- Sandbox code execution uses session-scoped containers

**Example**:
```bash
curl -X POST http://localhost:8083/v1/responses/chat/completions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Thread-Id: my-thread-123" \
  -H "X-Session-Id: my-session-456" \
  -d '{
    "model": "agentic-framework:scientific-agent-v1",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

## Streaming Patterns

### Server-Sent Events (SSE)

The Response API uses SSE for real-time streaming:

```python
import httpx

url = "http://localhost:8083/v1/responses/chat/completions"
headers = {
    "Authorization": f"Bearer {token}",
    "Content-Type": "application/json",
    "X-Thread-Id": "my-thread"
}
data = {
    "model": "agentic-framework:scientific-agent-v1",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": True
}

with httpx.Client() as client:
    with client.stream("POST", url, headers=headers, json=data, timeout=60.0) as response:
        for line in response.iter_lines():
            if line.startswith("data: "):
                chunk_data = line[6:]  # Remove "data: " prefix
                if chunk_data == "[DONE]":
                    break
                # Process chunk_data JSON
```

## State Management

### PostgreSQL Checkpointing

The Response API uses **LangGraph checkpointing** for conversation state:

```python
# Shared singleton checkpointer (Session 26 pattern)
from ...hybrid_orchestration import hybrid_service

# State isolation via thread_id
checkpoint_tuple = await hybrid_service.checkpointer.aget_tuple(
    {"configurable": {"thread_id": thread_id}}
)
```

**Database Tables**:
- `checkpoints`: Agent state snapshots
- `checkpoint_writes`: State update history
- `checkpoint_blobs`: Large binary data (files, plots)

**Session Lifecycle**:
1. Client creates thread: `POST /v1/threads`
2. Client sends messages: `POST /v1/responses/chat/completions` with `X-Thread-Id`
3. Agent state persists across requests via thread_id
4. Client retrieves history: `GET /v1/threads/{thread_id}/messages`

### Singleton Checkpointer Pattern (Session 26)

**Critical Design**: Use **shared singleton checkpointer** to minimize PostgreSQL connections.

**Implementation**:
```python
# ✅ CORRECT: Use shared singleton
from ...hybrid_orchestration import hybrid_service

agent = await ScientificWorkflowAgent.create(
    mcp_session_id=session_id,
    thread_id_override=thread_id,
    checkpointer=hybrid_service.checkpointer  # Shared, not per-request
)

# ❌ WRONG: Per-request instantiation
from ...persistence import AsyncPostgresSaver
checkpointer = AsyncPostgresSaver()  # Creates 2 new DB connections
```

**Benefits**:
- **Connection Reduction**: 80-85% fewer database connections
- **State Isolation**: Thread IDs provide proper separation
- **Lifecycle Management**: Service manages checkpointer disposal

**Documentation**: `docs/implementation-plans/SessionLevelSingletonCheckpointerPattern_20251217.md`

## Authentication

### JWT Token Flow

1. **User Login**: Client authenticates with Keycloak
   ```bash
   curl -X POST http://keycloak:8180/realms/master/protocol/openid-connect/token \
     -d "grant_type=password" \
     -d "client_id=validation-runner-client" \
     -d "client_secret=$CLIENT_SECRET" \
     -d "username=notebook-user" \
     -d "password=notebook-password"
   ```

2. **Extract Token**: Response contains `access_token` (JWT)
   ```json
   {
     "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI...",
     "expires_in": 300,
     "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI..."
   }
   ```

3. **API Request**: Include token in Authorization header
   ```bash
   curl -X POST http://localhost:8083/v1/responses/chat/completions \
     -H "Authorization: Bearer $ACCESS_TOKEN" \
     -H "X-Thread-Id: my-thread" \
     -d '{"model": "agentic-framework:scientific-agent-v1", ...}'
   ```

### Service-to-Service Authentication

**Client Credentials Flow** (for service accounts):
```bash
curl -X POST http://keycloak:8180/realms/master/protocol/openid-connect/token \
  -d "grant_type=client_credentials" \
  -d "client_id=validation-runner-client" \
  -d "client_secret=$CLIENT_SECRET"
```

**Use Cases**:
- CLI commands (A2A registration)
- Background processes (credential refresh)
- Service health checks

**Files**:
- `src/agentic_framework_sdk/cli/a2a_commands.py` - CLI authentication
- `src/agentic_framework_pkg/core/service_credentials_manager.py` - Service token management

### OpenAI-Compatible Error Format

```json
{
  "error": {
    "message": "Invalid thread ID format",
    "type": "invalid_request_error",
    "param": "thread_id",
    "code": "invalid_thread_id"
  }
}
```

**HTTP Status Codes**:
- `400`: Invalid request (bad parameters)
- `401`: Authentication failure (invalid/expired token)

- `500`: Internal server error
- `503`: Service unavailable (downstream dependency failure)

### LiteLLM Integration

**CRITICAL**: LiteLLM **automatically adds "Bearer " prefix** to tokens.

```python
from litellm import completion

response = completion(
    model="adept/scientific-agent-v1",  # LiteLLM-compatible alias
    messages=[{"role": "user", "content": "Hello"}],
    base_url="http://localhost:8083/v1",  # Already includes /v1
    api_key=token,  # ✅ Raw token (no "Bearer " prefix)
    extra_headers={"X-Thread-Id": thread_id},
    stream=True
)
```

**Common Pitfalls**:
- ❌ `api_key=f"Bearer {token}"` → Double Bearer prefix → 401 error
- ❌ `base_url="http://localhost:8083/v1/v1"` → Duplicate /v1 → 404 error
- ❌ `model="scientific-agent-v1"` → Missing provider prefix → 404 error

**Model Aliases**:
- `adept/scientific-agent-v1` (LiteLLM-compatible)
- `agentic-framework:scientific-agent-v1` (native format)

## Migration from Assistants API

### Key Differences

| Feature | Assistants API | Response API |
|---------|---------------|--------------|
| **Endpoint** | `/v1/assistants/*/runs` | `/v1/responses/chat/completions` |
| **State Management** | Assistant + Thread + Run | Thread + Messages |
| **Streaming** | Limited (runs only) | Full SSE support |
| **Tool Calling** | Via assistant tools | Native OpenAI format |
| **Complexity** | High (3 resource types) | Low (1 endpoint) |

### Migration Pattern

**Before (Assistants API)**:
```python
# Create assistant
assistant = client.beta.assistants.create(
    name="My Assistant",
    model="gpt-4",
    tools=[{"type": "code_interpreter"}]
)

# Create thread
thread = client.beta.threads.create()

# Create message
client.beta.threads.messages.create(
    thread_id=thread.id,
    role="user",
    content="Hello"
)

# Create run
run = client.beta.threads.runs.create(
    thread_id=thread.id,
    assistant_id=assistant.id
)

# Poll for completion
while run.status != "completed":
    run = client.beta.threads.runs.retrieve(thread_id=thread.id, run_id=run.id)
```

**After (Response API)**:
```python
# Create thread
thread = client.threads.create()

# Send message with streaming
response = client.responses.chat.completions.create(
    model="agentic-framework:scientific-agent-v1",
    messages=[{"role": "user", "content": "Hello"}],
    thread_id=thread.id,
    stream=True
)

for chunk in response:
    print(chunk.choices[0].delta.content, end="")
```

**Benefits**:
- **Simpler**: Single endpoint vs multiple resources
- **Faster**: Direct response vs polling loop
- **Streaming**: Real-time feedback
- **Standard**: OpenAI Responses API compatible

## Best Practices

### 1. Always Use Response API for New Work

```python
# ✅ CORRECT: Use Response API
response = client.responses.chat.completions.create(...)

# ❌ AVOID: Assistants API (legacy compatibility only)
run = client.beta.threads.runs.create(...)
```

### 2. Provide Thread ID in Headers

```python
# ✅ CORRECT: X-Thread-Id header
headers = {
    "Authorization": f"Bearer {token}",
    "X-Thread-Id": thread_id
}

# ❌ WRONG: Missing thread ID (stateless request)
headers = {"Authorization": f"Bearer {token}"}
```

### 3. Use Raw Tokens with LiteLLM

```python
# ✅ CORRECT: Raw token
response = completion(api_key=token, ...)

# ❌ WRONG: Manual Bearer prefix
response = completion(api_key=f"Bearer {token}", ...)
```

### 4. Don't Duplicate /v1 in URLs

```python
# ✅ CORRECT: URL already includes /v1
base_url = "http://localhost:8083/v1"
response = completion(base_url=base_url, ...)

# ❌ WRONG: Duplicate /v1
response = completion(base_url=f"{base_url}/v1", ...)
```

### 5. Use Shared Checkpointer

```python
# ✅ CORRECT: Shared singleton
from ...hybrid_orchestration import hybrid_service
agent = await ScientificWorkflowAgent.create(
    checkpointer=hybrid_service.checkpointer
)

# ❌ WRONG: Per-request instantiation
checkpointer = AsyncPostgresSaver()
```
